# Трезвый вечер — ТЗ на MVP «Проактивные сценарии»

Версия документа: 0.2 (23.10.2026) — реализовано в 1.1.0, см. «Отклонения от ТЗ» в конце
Репозиторий: https://github.com/Dezzpil/trezvy-vecher (Android, Java + HTML, данные в internal storage, экспорт ZIP: journal.md, data.json, audio/)

## 1. Позиционирование и границы

- Поддержка изменения привычки вечернего употребления. Не лечение, не ведение отмены алкоголя.
- Пилот: Россия, русский язык, взрослые 18+, закрытая группа для кастдева.
- В онбординге и в разделе «О приложении» явно: при длительном ежедневном употреблении, симптомах отмены (тремор, потливость, тревога, бессонница, галлюцинации) — к врачу-наркологу; приложение не заменяет врача и психолога.

### Входит в MVP
1. Всё существующее остаётся: записи тяги, чекпоинты дня, голосовые заметки, серии, советы, таймер волны, экспорт.
2. Анкета предпочтений и ограничений (можно пропустить и дополнить позже).
3. Встроенная библиотека сценариев (≈30–40 карточек) в виде JSON-пакета в assets.
4. Ранние запланированные предложения: дневное «планирование вечера» до того, как решение сформировано.
5. Алгоритмический подбор по правилам + учёт обратной связи.
6. Журнал взаимодействий со сценариями (локально), включён в экспорт.
7. Ветка «всё равно выпью»: одно небольшое изменение автоматизма.

### Не входит (следующие версии)
- Аккаунты, сервер, синхронизация (но модель данных к ним готова).
- Бэк-офис / редактор сценариев (формат пакета к нему готов).
- Карты, геолокация, поиск, каталоги книг/фильмов, события.
- ML-модели (деревья решений и т.п.) — только сбор данных и интерфейс ранжировщика.
- LLM, платная подписка.

## 2. Ключевая продуктовая логика

Решение «выпить» к вечеру обычно уже принято, поэтому основная проактивность — раньше:

| Окно (по умолчанию, настраивается) | Что происходит |
|---|---|
| 14:00–16:00 «План вечера» | «Как хочется провести вечер?» → выбор потребности → 2 сценария → «запланировать на 19:00» |
| За 30–60 мин до обычного «опасного» времени | Напоминание о выбранном плане или новое короткое предложение |
| Вечер, по кнопке «Хочу выпить / Хочу вечер иначе» | Реактивный подбор (существующий экран тяги + сценарии) |
| Утро (существующий чекпоинт) | Добровольно: «Получилось вчера то, что планировал?» |

Правила инициативы: не более N (по умолчанию 2) проактивных уведомлений в день, тихие часы, отключение одним переключателем, текст уведомления не обязан упоминать алкоголь.

## 3. Модель данных

Общие принципы (чтобы потом без боли перенести на сервер):
- Все id — UUID v4 (строка), генерируются на устройстве.
- Время — UTC ISO 8601 / epoch ms + отдельно `tz_offset_min` и локальная дата `local_date` (для аналитики «вечер»).
- У каждой пользовательской записи: `created_at`, `updated_at`, `deleted_at` (soft delete), `sync_state` (`local|pending|synced`), `schema_version`.
- Локальный `install_id` (UUID) — сейчас владелец данных; в v2 к нему привяжется `user_id`.
- Хранилище: SQLite (Room) вместо/рядом с текущим JSON. Миграция существующих данных — однократно при обновлении; старый формат продолжает поддерживаться в экспорте.
- Контент (сценарии) и пользовательские данные — разные хранилища: контент read-only пакет, пользовательские данные — БД.

### 3.1. Контент: пакет сценариев (read-only, из assets, позже с сервера)

```
ContentPack
  pack_id            "core-ru"
  version            "1.0.0"       // semver пакета
  min_app_version    int
  published_at
  locale             "ru-RU"
  taxonomy           { needs[], categories[], decline_reasons[], tags[] }
  scenarios[]        Scenario
  flows[]            Flow
```

```
Scenario                     // карточка-занятие
  id                 "three_odd_details"   // стабильный, не меняется
  revision           int                   // растёт при любом изменении текста/условий
  status             active|disabled
  title
  category           adventure|comfort|interest|body|social|pause|alcohol_shift
  needs[]            leave_me_alone|switch_off|novelty|company|comfort|movement|...
  setting            home|outdoors|any
  duration_min, duration_max   // минуты
  effort             1..3
  cost               0|1|2      // бесплатно/немного/по ситуации
  social             solo|with_close|among_people
  novelty            1..3
  requires[]         can_leave_home|headphones|book|game|kitchen|shower|phone_camera|...
  excludes_if[]      ограничения анкеты: no_outdoors_evening|mobility|noise|kids_at_home|...
  intoxicated_ok     bool       // допустим ли после употребления (прогулки/физуха — false)
  variants[]         ScenarioVariant  // короткий / обычный / «мало сил»
  fallback_id        id сценария-замены (например домашняя версия прогулки)
  followup           { question, scale: better_same_worse, ask_craving: bool, delay_min }
  tags[]
  author, notes      // для будущего редактора
```

```
ScenarioVariant
  key                short|default|low_energy
  text               текст предложения
  steps[]            короткие шаги инструкции (опционально)
  stop_permission    «Не зашло — можно бросить через 2 минуты»
```

```
Flow                         // простой сценарий разговора
  id, revision
  trigger            day_plan|pre_evening|craving_button|still_drink|morning
  entry_node
  nodes[]            Node
```

```
Node
  id
  type               question|offer|instruction|feedback|end
  text
  options[]          { key, label, sets: {context_key: value}, next }   // для question
  offer              { count: 2, diversity: category, filter_overrides } // для offer
  on                 { accepted: node, declined: node, none_fit: node, timeout: node }
```

Ограничения типов узлов — только эти пять; произвольный граф и скрипты не допускаются (проще валидация и будущий редактор). Валидатор пакета (юнит-тест в CI): все `next` существуют, нет недостижимых узлов, у каждого `offer` есть ветка `none_fit`, все `needs/requires` есть в таксономии.

## 4. Подбор (ранжировщик)

Интерфейс, одинаковый для правил и будущего ML:

```
rank(context, profile, history, candidates) -> [ {scenario_id, variant_key, score, features} ]
```

rules-v1:
1. Жёсткие фильтры: `excludes_if` × профиль; `requires`; `setting` × «могу выйти»; длительность ≤ доступного времени; `intoxicated_ok` при `intoxicated`; `blocked`; показанные за последние 3 дня.
2. Счёт: совпадение `needs` с текущей потребностью (+3), прошлые `better` (+2 за каждый, с затуханием), `accepted` (+1), отказ `dislike` (−5, после 2 раз — скрыть категорию с вопросом), `too_hard` → понизить `effort` в следующий раз, `cant_now` — не штрафовать сценарий.
3. Новизна: с вероятностью ~15% один из двух слотов — сценарий из `curious_to_try` или ранее не показанный (exploration, нужно для будущего обучения).
4. Разнообразие: два варианта из разных категорий.
5. Если кандидатов < 2 — `fallback_id`, затем «пауза без задач».

В `offer.features` сохраняются все признаки и `score` — это и будет датасет для деревьев решений в v2.

## 5. Ветка «всё равно выпью»

Триггер: в сессии дважды `none_fit` или явная кнопка «Не хочу альтернатив, буду пить».
- Ответ без уговоров: «Понял. Давай изменим хотя бы одну вещь в привычном вечере».
- Сценарии категории `alcohol_shift`: без привычного фонового видео; выбрать музыку осознанно; сесть в другом месте квартиры; заранее решить, сколько, и оставить остальное в холодильнике; чередовать с водой; через 30 минут отметить, отличается ли вечер.
- Запрещено в контенте: увеличение количества, новые напитки, выход на улицу/активность после употребления, слова «награда», «приключение с пивом».
- Утром — нейтральный вопрос без обнуления серий за честный ответ.

## 7. Экраны (Android)

1. Онбординг: дисклеймер 18+ и «не лечение», короткая анкета (пропускаемая), время уведомлений.
2. «План вечера»: потребность → силы/время → 2 карточки → «Сделаю сейчас / Запланировать / Ничего не подходит (причина)».
3. Карточка сценария: текст, шаги, «Попробую», «Не сейчас».
4. Обратная связь через `followup.delay_min` (уведомление или при следующем открытии).
5. Расширение существующего экрана тяги: кнопка «Попробовать что-то другое».
6. История: показанные/попробованные сценарии, избранное, «больше не предлагать».
7. Настройки: уведомления, тихие часы, анкета, экспорт/удаление данных.

## 8. Экспорт и приватность

- В ZIP добавляются `scenarios.json` (сессии, показы, ответы, отзывы) и версия пакета.
- Удаление всей истории — одной кнопкой с подтверждением.
- Геолокация, контакты, фото не собираются. Фото из заданий остаются в галерее пользователя.
- В v2 при синхронизации: явное согласие, отдельно — согласие на будущий ИИ-анализ. Учесть 152-ФЗ (локализация ПДн граждан РФ на серверах в РФ, данные о здоровье — специальная категория).

## 9. Метрики пилота

- Доля дней с открытием «Плана вечера» по уведомлению.
- Показ → принято → попробовал → лучше (по сценарию и ревизии).
- Причины отказов по категориям.
- Самооценка тяги до/после (где ответили).
- Утренний ответ «пил вчера: нет/меньше/как обычно».
- Отключения уведомлений и удаления (сигнал навязчивости).
- Качественно: интервью с участниками каждые 1–2 недели.

## 10. Этапы реализации

1. Room + миграция текущих данных на UUID; event_log.
2. Формат пакета, валидатор в CI, стартовые 36 карточек и 4 flow (day_plan, pre_evening, craving_button, still_drink).
3. Движок flow + ранжировщик rules-v1.
4. Экраны плана, карточки, обратной связи; интеграция с экраном тяги и утренним чекпоинтом.
5. Уведомления (WorkManager/AlarmManager, POST_NOTIFICATIONS на Android 13+), тихие часы, лимиты.
6. Экспорт/удаление, история.
7. Сборка APK для закрытой группы.

## 11. Критерии приёмки

- Существующие функции и данные работают после обновления без потерь.
- Любой сценарий открывается без интернета.
- Не предлагаются сценарии, противоречащие анкете или `intoxicated_ok`.
- Каждый показ пишет `offer` с ревизией сценария, ranker_id и features.
- «Не ответил» хранится как null, не как отрицательный результат.
- Уведомлений не больше лимита, тихие часы соблюдаются.
- Невалидный пакет не проходит CI.
- Экспорт содержит новые данные, удаление стирает всё.

## Отклонения от ТЗ в реализации 1.1.0

- **Хранилище — не Room/SQLite, а тот же `data.json`.** Интерфейс приложения целиком в WebView, данные уже жили в JSON; перенос в SQLite потребовал бы переписать всю работу с данными через мост. Структура при этом табличная: каждая коллекция = будущая таблица, у записей UUID и поля синхронизации. Переход на SQLite/сервер — в v2 вместе с аккаунтами.
- **Старые записи сохраняют прежние id** (на них ссылаются имена аудиофайлов); UUID получают все новые записи.
- **Утренний вопрос** — быстрый ответ «получилось / частично / нет» в утреннем чекпоинте; «пил вчера» берётся из «Итога дня» и привязывается к сегодняшним сценариям (`drank_tonight: yes|no`, `cans`).
- **Варианты карточек:** `default` обязателен, `short` и `low_energy` — там, где имеют смысл.
- **Дневное окно:** «План вечера» в 14:00, «Перед вечером» — за час до времени из анкеты (по умолчанию 18:00). Лимит — 2 проактивных уведомления в день (план, перед вечером, «как прошло?»); напоминания о запланированном пользователем занятии в лимит не входят. «Перед вечером» не приходит, если на сегодня уже есть план.
- **Исследование:** 15% — один из двух слотов отдаётся ещё не показанному сценарию или сценарию с тегом из «любопытно попробовать»; помечается `features.explore = 1`.
- **Отказ «не люблю такое» дважды** скрывает сценарий; «не могу сейчас» не штрафует и подставляет `fallback_id`; «слишком много сил» снижает силы до минимума в текущем разговоре.

## Версия 1.2.0 — «Равновесие» (одна механика)

Пользовательский запрос: убрать разделение на «пассивный дневник» и «Хочу провести вечер иначе» как отдельную кнопку; сделать одну линию, одну балансирующую механику; сильно расширить варианты, мыслить через пространство; выровнять кнопки и добавить переходы.

- **Шесть сторон дня:** Тело, Руки, Голова, Люди, Мир, Тишина. Ход засчитывается стороне: «сделал» = 1, «частично» = 0,5. Цель — хотя бы по одному ходу на каждую сторону в день. Колесо на главном экране, недельное колесо в «Балансе».
- **Места:** диван, комната, кухня, ванная, окно/балкон, подъезд/двор, дорога, работа, город. Место выбирается одним касанием или угадывается по времени и анкете (будни 9:30–17:30 — работа, 17:30–19:00 — дорога). Ходы-переходы (`kind: transition`, поле `to`) меняют место — «встать с дивана», «к окну», «на лестницу», «выйти на остановку раньше». После 40 минут на одном месте переходы поднимаются выше.
- **Линия дня** вместо отдельных экранов: прошлое (отметки, тяга с «Отпустило / Выпил», сделанные ходы, смены места, голос), узел «Сейчас» (режим «Сейчас / На вечер», место, «Тянет 0–10», карточка хода, «Уже выпил», «Всё равно выпью»), будущее (запланированные ходы, чекпоинты). Пропущенные чекпоинты сворачиваются в одну строку.
- **Карточка хода:** «Другое / Позже / Делаю»; в режиме «На вечер» — время и «В план». Во время хода — шаги, таймер, заметка или голос; затем «Хуже / Так же / Лучше». Цепочки `then` предлагают следующий ход.
- **Тяга** отмечается прямо на линии: сила, «чего на самом деле хочется» (влияет на стороны), триггеры, «Волна, 10 мин», «Мои причины»; при ≥7 — только короткие лёгкие ходы, при ≥8 — предупреждение о враче.
- **«Всё равно выпью»** включает на сегодня режим одного изменения (10 ходов `sector: shift`), без уговоров; «Уже выпил» оставляет только безопасные ходы дома.
- **Контент 2.0:** 155 ходов (тело 28, руки 33, голова 26, люди 17, мир 19, тишина 22, изменения 10). Новое: уборка «угла, который бесит», мелкий ремонт, разбор ящика, готовка, дыхательные техники, «5-4-3-2-1» с записью, ходы в подъезде и на дороге, работа, город — библиотека с разговором с библиотекарем, бассейн, баня, скалодром, музей, лекции, клуб настольных игр, мастер-классы, приют для животных.
- **Подбор `balance-v1`** — см. README. Данные: schema 3 (`places_log`, `now`); миграция с 1.1 без потерь.
- **UI:** кнопки фиксированной высоты в сетке без переноса строки, шторки снизу, переходы между вкладками, выезд и смена карточки, «полёт» точки в колесо, лепестки с пружиной; уважается `prefers-reduced-motion`.
